- Clause 9: security considerations.

Reference pipeline:

SRC -> C -> PP -> M -> P -> D -> SINK

Reference functions:

- SRC supplies input data.
- C collects data from one or more sources.
- PP cleans, aggregates, or preprocesses collected data.
- M performs machine-learning processing.
- P applies policies to model output.
- D identifies destinations and distributes output.
- SINK receives the output on which action may be taken.

Amba-Gov interprets this pipeline for its project architecture and extends it
with:

- Ethiopian legal-applicability handling;
- source hierarchy;
- authorization and guardian controls;
- institutional mandates;
- human approval;
- governance conflict resolution;
- project safeguards;
- tamper-evident audit records;
- project-level readiness assessment.

Amba-Gov does not claim formal Y.3172 conformance. The Y.3172 P node is not
represented as an Ethiopian regulator or as an independent source of statutory
authority.

9. CLAIM AND REPORTING LIMITATIONS

Amba-Gov does not claim that:

- an unreviewed source has received legal review;
- a translation is official without evidence;
- UNICEF or UNESCO guidance independently creates Ethiopian legal duties;
- the STME supporting document is formally adopted national policy;
- ESDP VI remains current after 2024/25 without qualification;
- the Y.3172 P node is a regulator;
- Amba-Gov formally conforms to Y.3172;
- Amba-Gov is certified by ITU;
- a readiness score represents Ethiopia's national readiness;
- a test passed without successful test execution;
- an action executed without an execution receipt;
- an operation was delivered without acknowledgment;
- absence of a provision in the current corpus proves that no applicable law
  exists;
- artifact-integrity verification constitutes legal review;
- existence of source code proves maturity;
- existence of a test file proves successful test execution.
